為什麼需要

LLM 很強，但會一本正經地講錯

  • LLM 有三個主要問題：會講錯、知識過時、無法追溯出處
  • Hallucination：講出聽起來很像真的、但其實是錯的內容
  • 例子：問 BART 中耳是什麼，它說中耳介於中耳和鼻子之間
  • 遇到需要最新資訊、或超出訓練資料的問題，特別容易出錯

今天的大型語言模型，也就是 LLM，很會寫也很會聊，但它有三個主要問題：會講錯、知識會過時，而且說不出答案是從哪裡來的。其中最麻煩的是 hallucination，就是模型講出聽起來很像真的、其實是錯的內容。例如問 BART 中耳是什麼，它竟然回答中耳是介於中耳和鼻子之間的部分。

為什麼需要

只靠「背」的知識，有兩個天生限制

  • 模型的知識存在參數裡，就像「背起來」的
  • 限制一：不知道訓練之後才發生的事
  • 限制二：很難記住訓練資料中很少出現的知識
  • 背進去的知識很難更新，也說不出答案的出處

2 / 13
模型的知識，大部分是在訓練時「背」進參數裡的。這帶來兩個根本限制：它不知道訓練之後才發生的事，也很難記住訓練資料裡很少出現的冷門知識。而且背進去的知識很難更新或擴充，模型也說不出答案的出處。

是什麼

RAG：先查資料，再回答

  • RAG：讓 LLM 先從外部知識庫找出相關資料，再根據資料回答
  • 結合兩種記憶：參數裡「背的」知識＋外部「翻的」資料
  • 外部資料可以直接修改和擴充，用了哪些資料也能被檢查
  • 這個名稱來自 2020 年 Lewis et al. 的論文

3 / 13
RAG 的想法很簡單：先從外部的知識庫找出相關資料，再根據這些資料回答。它把兩種記憶結合起來，一種是模型自己背在參數裡的知識，另一種是需要時才去翻的外部資料。外部資料可以直接修改和擴充，而且模型用了哪些資料，也能被檢查。

是什麼

比喻：從閉書考變成開書考

  • 閉書考：只能靠腦袋裡背的東西作答
  • 開書考：先翻課本找到相關段落，再用自己的話寫答案
  • RAG 就是讓模型參加開書考
  • 在 open-domain QA 上，參數少很多的開書考模型，能勝過參數多很多的閉書考模型
  • 比喻的極限：模型可能翻到不相關的頁面

原始 RAG 論文自己就把只靠參數的方法叫 closed-book，把會去檢索資料的方法叫 open-book。在 open-domain QA 的 NQ 資料集上，RAG-Sequence 只有 626M 個可訓練參數，拿到 44.5 分。參數多很多的 T5-11B 有 11B 個參數，卻只有 34.5 分。不過要注意，開書考的學生通常知道該翻哪一章，RAG 卻可能翻到不相關的頁面。

是什麼

知識過時了？換一本新版課本就好

  • 課本過時了，不必重上一整年的課，換一本新版課本就好
  • RAG 也一樣：換掉外部資料，就能更新知識
  • 換成 2018 年版的 index：答對 2018 年的世界領袖 68%
  • 用 2016 年版的 index 問 2018 年的領袖：只剩 4%

原始 RAG 論文做了一個實驗：準備 82 位在 2016 到 2018 年間換人的世界領袖，問模型某個職位現在是誰。換成 2018 年版的 index，模型答對 68%；但如果還用 2016 年的舊 index 去問 2018 年的領袖，就只剩 4%。所以只要換掉外部資料，就能更新 RAG 的知識，不用重新訓練模型。

怎麼運作

三個步驟：建索引、找資料、寫答案

  • Indexing：把文件切成 chunk，轉成向量，存進資料庫
  • Retrieval：把問題也轉成向量，找出最相似的幾個 chunk
  • Generation：把問題和 chunk 組成 prompt，交給 LLM 寫答案
  • 比喻：圖書館員（retriever）找書，作家（generator）讀完寫答案

最基本的 RAG 流程只有三步。先把文件切成小段、轉成向量存起來；收到問題時，把問題也轉成向量，找出最相似的幾段。最後把問題和找到的段落一起交給 LLM 寫出答案，就像圖書館員先找書、作家再讀完書寫出回答。

怎麼運作

先切塊，再把意思轉成向量

  • Chunking：把長文件切成一小段一小段（chunk）
  • 為什麼要切：配合模型一次能處理的長度限制
  • 原始 RAG：每篇 Wikipedia 文章切成 100 個英文字一段，共 21M 段
  • Embedding：把一段文字的意思轉成一串數字（向量）
  • 副作用：切開之後，chunk 可能失去上下文

因為 language model 一次能處理的長度有限，所以要先把文件切成小段。每一段再用 embedding 轉成一串數字，意思相近的文字，就會被找成相似的結果。但切開也有副作用：像「公司營收比上一季成長 3%」這一段，沒說是哪家公司、哪個時期，就很難被找到。

怎麼運作

找資料：用意思找，也用字找

  • Retriever 負責查資料：從一大堆文件中找出最相關的幾份
  • Embedding 擅長找「意思相近」的內容
  • 但可能漏掉精確字串，例如錯誤碼「TS-999」
  • BM25 靠字面比對，專門找精確的詞
  • 兩種一起用，比只用 embedding 好

負責找資料的元件叫 retriever，它找到的文件好不好，直接影響答案好不好。就像問圖書館員有沒有講心臟病的書，館員會依意思推薦，這就像 embedding；但要找書號「TS-999」，就該直接比對字串，這就像 BM25。實驗也發現，embedding 加上 BM25，比只用 embedding 好。

進階變體

基本版不夠用：Naive → Advanced → Modular

  • 基本版（Naive RAG）會找不準：選到不相關的、漏掉關鍵的
  • 也會寫錯：產生檢索內容沒有支持的說法
  • 還回答不了「這批資料的主要主題是什麼」這種問題
  • 綜述把 RAG 分成 Naive、Advanced、Modular 三種典範
  • ⚠️ 這是分類方式，不完全等於時間先後

剛剛講的是最基本的版本，叫 Naive RAG。它常常找不準，也會寫出檢索內容沒有支持的說法，而且答不了需要看完整批資料的大問題。為了改善這些缺點，綜述又整理出 Advanced RAG 和 Modular RAG，它們都是在 Naive RAG 的基礎上逐步改進。

進階變體

兩個例子：Self-RAG 與 GraphRAG

  • 問「美國各州的名字怎麼來的」：一般 RAG 寫出和文件不一致的答案
  • Self-RAG：先判斷要不要查，再為每段打分數，選出最好的那段
  • 寫暑假作文這種題目，就不用查
  • GraphRAG：先把整批資料整理成關係圖和摘要，回答「整體主題」這類大問題
  • 代價：事先建 index 很花時間

同樣問美國各州的名字怎麼來的，一般 RAG 寫說 California 是以 Christopher Columbus 命名，和它自己找到的文件對不上。Self-RAG 則是每寫一段前先判斷要不要查，再為每段打分數，最後選中「11 個州以人名命名」那段，因為它完全被文件支持。GraphRAG 適合「這批資料的主要主題是什麼」這種大問題，在 Podcast 資料上，GraphRAG 等全局方法的全面性勝率是 72%–83%。

怎麼評估

評估要分開看：找得好不好、寫得好不好

  • 「找資料」和「寫答案」要分開評估
  • Context relevance：找來的資料切不切題
  • Faithfulness：答案是不是忠於找來的資料
  • Answer relevance：答案有沒有直接回答問題
  • ⚠️ 這三個分數適用於一般 RAG，不適合「整批資料的主題」這類問題

評估 RAG 時，要分開看「找得好不好」和「寫得好不好」。就像老師改開書考，會分開看翻對頁了沒、有沒有亂掰、有沒有離題，才知道學生是哪裡出問題。RAGAS 這類工具不需要標準答案，而是把判斷拆成小步驟讓 LLM 評分。不過 faithfulness 高，不代表答案就是對的，因為找來的資料本身也可能有錯。

總結

重點回顧：RAG 有用，但不是萬靈丹

  • RAG = 先查再寫；換掉 index 就能更新知識，不用重新訓練
  • 位置有影響：放在中間的資訊最容易被忽略（Lost in the Middle）
  • GPT-3.5-Turbo、20 份文件、答案在中間：53.8%，低於不給文件的 56.1%
  • ⚠️ 文件放越多越好嗎？各研究看法不一；有實驗發現 50 份比 20 份只多約 1%–1.5%
  • 檢索不一定有幫助，外部資料本身也可能有錯

最後幫大家整理：RAG 就是先查再寫，只要換掉 index，就能更新 RAG 的知識，不用重新訓練模型。但它不是萬靈丹：在 GPT-3.5-Turbo 的實驗裡，20 份文件中答案放在第 1 份時答對 75.8%，放在中間只有 53.8%，比完全不給文件的 56.1% 還低，這是在 20 和 30 份文件設定的最差位置觀察到的。另一份研究也發現，ChatGPT 加上檢索後，PubHealth 反而從 70.1 降到 54.7。至於要放幾份文件，各研究的看法並不一致，例如有一項實驗發現，取 50 份比 20 份只多進步約 1%–1.5%，而外部資料本身也可能有錯。
